# 部署与服务器

> 适用范围：Ubuntu 自建同步服务（`apps/sync_server_ubuntu`）、Docker Web（`apps/pass-web`）、TLS、macOS 本机 `.app` 安装。
> 原则：服务器本地配置不在仓库里，换机/重装必须重做；本机 macOS 与 Ubuntu 环境不要混用。

## 1. 同步服务首次上线：四项本地配置缺一不可

1. **Bearer Token 文件** `/etc/pass-sync/tokens.conf`
   ```bash
   PASS_SYNC_NEW_BEARER_TOKEN='<Token>' \
     /opt/pass-sync-source/apps/sync_server_ubuntu/rotate_token.sh /etc/pass-sync/tokens.conf default
   chown pass:pass /etc/pass-sync/tokens.conf && chmod 0600 /etc/pass-sync/tokens.conf
   ```
   `chown` 不能省：脚本以 root 建 `0600` 文件，服务以 `pass` 用户运行，只改权限位不改属主会读不到。服务端要求 `mode & 0o077 == 0`。
2. **监听地址** `/etc/pass-sync/pass-sync-server.env`：unit 默认 `PASS_SYNC_HOST=127.0.0.1`，外部设备连不上。对外必须显式 `PASS_SYNC_HOST=0.0.0.0` + `PASS_SYNC_PORT=5443`；`EnvironmentFile=-…env` 在 `Environment=` 之后，会覆盖 unit 默认值。
3. **TLS 证书**：`deploy.sh` 自动识别 `/etc/bz/certs/server.crt|server.key`，复制到 `/etc/pass-sync/tls/` 并写入 `PASS_SYNC_TLS_CERT/KEY`；通配证书 SAN `DNS:*.sbbz.tech` 可覆盖子域。续期后要重跑部署才会同步。
4. **GitHub Secrets**：`SYNC_SERVER_HOST` 必须是当前主机（域名或真实 IP），`SYNC_SERVER_USER`/`SYNC_SERVER_SSH_KEY` 仍能登录：
   ```bash
   gh secret set SYNC_SERVER_HOST --repo pixian5/passkey --body "or.sbbz.tech"
   ```
**出处**：`docs/20261013-0153-同步服务首上线or.sbbz.tech与部署脚本两处修复-Step-5-Preview.md` §3

## 2. 部署脚本的两个真实缺陷（写脚本时避开）

1. **通配符 SAN 让健康检查必然失败**：`grep -oE 'DNS:[A-Za-z0-9.-]+'` 遇到 `DNS:*.sbbz.tech` 时 `*` 不在字符类，只能匹配到 `DNS:`，`sed` 后为空 → 判定失败 → `trap ERR` 自动回滚。修复：逐条读 SAN，跳过含 `*` 的项，取第一个具体域名。
2. **安装后版本恒为 unknown**：`_read_service_version()` 只读 `Path(__file__).parents[2]/VERSION`，装到 `/opt/pass-sync-server/` 后 `parents[2]` 是 `/`。修复：按 `PASS_SYNC_VERSION_FILE` → 同级 → 上一级 → 上两级 依次尝试；`deploy.sh` 把仓库 `VERSION` 装到 `${INSTALL_DIR}/VERSION` 并加入 `managed_paths`（备份/回滚一起绑定）。
**出处**：`docs/20261013-0153-…-Step-5-Preview.md` §4

## 3. 认证与开放模式必须显式，默认拒绝

- 无 Token 时服务**拒绝启动**；只有显式 `PASS_SYNC_ALLOW_OPEN=1` 才开放，且仅用于本机开发，不得对公网开放。
- `start.sh`/launchd 默认监听 `127.0.0.1`；`install-launchd.sh` 要求显式开放开关，并把 `PASS_SYNC_ALLOW_OPEN` 持久进 plist。
- `PASS_SYNC_ALLOW_PLAINTEXT`（是否允许明文同步）与 `PASS_SYNC_ALLOW_OPEN`（是否允许无认证）**语义独立**，不要合并成一个开关。
- Token 建议 32 字节以上随机串；轮换流程：`rotate_token.sh`（含 `chown pass:pass`）→ `systemctl restart pass-sync-server` → 所有客户端同步更新。单字符 Token 等于公网暴破敞口。
**出处**：`docs/20260930-0048-同步补偿对账与服务器认证加固-GPT-6.md` §2.1、`docs/20261013-0153-…-Step-5-Preview.md` §7–8

## 4. 本机 Fake IP（TUN）会制造「服务器不通」的假象

**现象**：`dig or.sbbz.tech` 甚至指定 `1.1.1.1/8.8.8.8/223.5.5.5` 都返回 `198.18.1.93`（RFC 2544 段），据此判断服务器挂了。
**根因**：本机 TUN 的 Fake IP 模式劫持 DNS；CI runner 的 SSH 目标只取决于 Secrets 主机名，本机网络状况说明不了任何问题。
**正确做法**：用 DoH 取真实 IP，再直连验证：
```bash
curl -sS 'https://cloudflare-dns.com/dns-query?name=or.sbbz.tech&type=A' -H 'accept: application/dns-json'
nc -z -G 8 18.225.117.121 5443
curl -sS --resolve "or.sbbz.tech:5443:18.225.117.121" https://or.sbbz.tech:5443/healthz
```
**出处**：`docs/20261013-0153-…-Step-5-Preview.md` §5

## 5. Docker Web：单用户、单写实例、数据在卷里

- 容器内监听 `53335`，生产只映射 `127.0.0.1:53335`，由 Caddy/Nginx 提供 443/TLS；不用 `network_mode: host`。
- 业务进程以非 root（`passweb`）运行；`/data` 属主必须是 `passweb`，密钥文件 `0600`、目录 `0700`。named volume 优先于 bind mount，避免 UID/GID 漂移。
- 密码/Token/同步密钥只经 `env_file`（`0600`）或 Docker secrets，**不打进镜像**。
- 健康检查用 `/healthz`（不读保险库内容）；升级/回滚以固定镜像版本或 digest 为准，不靠 `latest`。
- 备份只备 `/data` 卷不够，要按宿主机策略备份；恢复时连同密钥文件一起，缺一不可。
**出处**：`docs/pass-web-docker-development-zh.md` §1–7、`docs/sync-protocol-v2.md`「Docker 容器替换与单实例锁」

## 6. 「创建同步服务」的端口与 TLS 规则（Tauri provisioning）

- 只接受 `https://`；带显式端口时通过 SSH 复制证书/私钥到 `/etc/pass-sync/tls/` 并以 HTTPS 执行 `/healthz`。
- 不监听 1–1023 特权端口，也不停/覆盖目标端口已有进程；安装前检查占用，被 Xray/bz 等占用时返回「端口已被其他进程占用」。
- 端口预检必须失败关闭：优先 `ss`，异常回退 `lsof`；两者都不可用或检查失败就中止，**不把空输出当空闲**。重建已有服务先暂存，再停旧服务并二次检查，失败尝试恢复旧服务。
- 首次 SSH 是无提示 TOFU（自动保存 `ssh-keyscan` 主机公钥）：只能发现后续主机密钥变化，不能证明首次身份；仅在可信网络使用，优先私钥认证。
- 证书必须是完整链（`fullchain.cer/pem`）+ 对应私钥，缺一创建失败。
**出处**：`docs/tls-provisioning-zh.md`

## 7. 部署验收与回滚

```bash
systemctl status pass-sync-server
journalctl -u pass-sync-server -n 50 --no-pager          # 版本行在这里
curl -sS --resolve sbbz.tech:5443:127.0.0.1 https://sbbz.tech:5443/healthz
ls -l /var/lib/pass-sync/backups
systemctl list-timers pass-sync-server-backup.timer
```
- 鉴权自检：无 Token 访问 `/v2/sync/state` 应 `401`；带 Token 且无数据应 `404`。
- 回滚：部署失败走 `deploy.sh` 的 trap；手动用 `/var/lib/pass-sync/backups/<stamp>-pre-deploy/installed/` 还原受管文件，再 `daemon-reload && restart`。
- 升级 SQLite 前先备份；旧/新服务进程绝不能同时写同一个数据库。
**出处**：`docs/20261013-0153-…-Step-5-Preview.md` §6–7、`docs/sync-protocol-v2.md` §Server concurrency

## 8. macOS 本机 `.app` 安装的两个坑

- `cp -R 新.app /Applications/同名.app` 会把新包嵌进旧包目录，形成 `/Applications/X.app/X.app`，不是替换。正确：确认旧进程退出 → 旧 `.app` 移到备份路径 → 复制新包 → 校验 `Info.plist` 的 `CFBundleShortVersionString` 与二进制时间戳。
- 直接运行 GUI 二进制的 `--version` 会挂住（无参数进入图形循环）；版本读 `Info.plist`，或用 `open -a` 后查进程验证。
**出处**：`docs/20260930-0048-…-GPT-6.md` §4
