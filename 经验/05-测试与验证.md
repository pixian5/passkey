# 测试与验证

> 适用范围：根级基线、扩展 Node 测试、Rust/Clippy、Python 同步服务、JS↔Rust 对拍、并发混沌、Safari 实测。
> 原则：测试数量会变，文档不写死数字，以命令输出为准；「环境不可用」不能记为通过。

## 1. 统一入口与失败分类

```bash
bash scripts/test_all.sh              # 默认：版本、扩展 JS、Python、Rust、对拍、命令矩阵、Markdown 链接
bash scripts/test_all.sh --docker     # 额外跑 Docker Web 生命周期（会构建镜像）
bash scripts/test_all.sh --android    # 额外跑 Android 单测（需 SDK/JDK）
```

- Cargo 默认用临时 target，避免仓库历史 `target/` 的权限或损坏产物污染结果；要复用缓存显式给 `CARGO_TARGET_DIR`。
- 脚本结尾分两类：**代码失败**（必须修）与**环境不可用**（缺 Node/Python/Cargo/依赖或显式请求的 Docker/Android 工具）；后者不得写成「通过」。
- 自定义 target 目录时，`core_gate.sh`、`check_domain_ffi.sh`、FFI 打包、对拍脚本都尊重 `CARGO_TARGET_DIR`。
**出处**：`docs/test-baseline-and-sync-e2e-zh.md` §1–2

## 2. 门禁是一票否决，本地要与 CI 一致

- Rust：`cargo clippy --all-targets --locked -- -D warnings` 对 `core/pass_core`、`apps/pass-web`、`apps/codex-tauri/src-tauri` 三个目标全部零警告；`cargo fmt --check` 三个 workspace 全过。本地 `test_all.sh` 与 CI `quality-gates` 使用同一严苛模式。
- Python：同步服务与脚本测试加 `-W error::ResourceWarning`，任何未关闭的文件/数据库句柄直接把测试判失败。
- 版本：`node scripts/version.mjs check` 必须显示 `VERSION_CHECK_OK <版本> (N entries)`；N 的变化要能解释（新增版本源）。
**出处**：`docs/20261104-1045-当前开发进度-antigravity.md` §2、`docs/20261104-1105-当前开发进度-antigravity.md` §2

## 3. Python SQLite：`with connection` 不等于关闭

**现象**：Python 3.12+ 测试出现 `ResourceWarning: unclosed database in <sqlite3.Connection object>`。
**根因**：`with sqlite3.connect(...) as conn:` 只提交/回滚事务，不调用 `close()`。
**正确做法**：只读审计与测试夹具统一用 `contextlib.closing`；需要写时补 `commit()`；不要靠忽略警告通过。
**出处**：`docs/test-baseline-and-sync-e2e-zh.md` §3、`docs/20261104-1105-…-antigravity.md` §1

## 4. 合并/同步测试的三层分工

1. **字段级合并、顺序数组、关系墓碑、永久删除安全**：Rust/JS 黄金向量 + 共享 Node 测试。
2. **传输层并发与耐久**：Python 服务端端到端测试。
3. **端侧行为**：Tauri / Docker Web Rust 测试 + 扩展后台测试。

JS↔Rust 必须对拍（`node js/check_merge_parity.mjs`，48 个确定性用例）；领域类型走 C ABI ctypes 对拍（`scripts/check_domain_ffi.sh`，输出 `DOMAIN_FFI_OK`）；命令矩阵用 `scripts/check_command_matrix.mjs`（当前 72 项）。任何一侧改了合并/安全规则，三处都要动。
**出处**：`docs/test-baseline-and-sync-e2e-zh.md` §4、`docs/20261104-1125-当前开发进度-antigravity.md`

## 5. 同步边界必须覆盖的用例清单

- 已有状态缺 `If-Match` → `428`；过期 ETag → `412` → 拉取/合并/重试。
- 相同 `Idempotency-Key` 重放只重放原响应，不增加 revision。
- 远端写入成功但响应丢失 → 回读确认已提交，不重复建版本。
- `412` 后回读失败 → 已应用到本地的候选仍进 outbox。
- outbox 重试用新键前先核对远端，已提交则清队列。
- 临时 `503` 后重试恢复且不重复历史版本。
- 恢复历史版本同时要求 `If-Match` + `Idempotency-Key`。
- WebDAV 有 ETag 时条件写；远端已有非空包但无 ETag 必须拦截。
- 无 Token 默认拒绝启动，仅显式 `PASS_SYNC_ALLOW_OPEN=1` 开放。
- 覆盖模式下两侧永久墓碑也不能被丢弃。
**出处**：`docs/test-baseline-and-sync-e2e-zh.md` §4

## 6. 并发混沌测试用「线程 + Barrier」制造真竞态

**做法**（`apps/sync_server_ubuntu/tests/test_concurrent_chaos.py`）：
- 两个客户端基于同一初始 revision 并发提交，用 `threading.Barrier` 保证同时命中服务端，验证 200 与 412 的分歧；
- 412 客户端自动拉取最新快照、字段级合并、带新 ETag 重试，最终双端收敛；
- 主密钥轮换（Key1→Key2）期间另一客户端提交旧密钥载荷，验证其 412 后基于新密钥重构；
- 相同 Idempotency-Key 重放不产生冗余版本；缺 `If-Match` 被 428 拦截。

**要点**：顺序执行的「伪并发」测不出这类问题；必须让两个请求真正同时到达。
**出处**：`docs/20261104-1125-…-antigravity.md` §1

## 7. 测试不能空转：三种典型假通过

1. **断言前置为空**：只比较调用前后集合长度，若前置就没数据，`0 === 0` 恒真。正确：先断言前置长度 ≥ 1，再按业务键（如 `rpId + userName`）精确断言目标不存在。
2. **测生产不可达路径**：路由层已让位，测试却直接用 `attestation: "direct"` 调桥接并断言成功，名字读起来像「该场景可用」。正确：用真实可达形态（`none`），并在测试里写明「只证明协议自洽，不代表 RP 接受」；拒绝路径单独测。
3. **`Array.prototype.includes` 当子串用**：它是精确元素匹配，不是子串匹配。错误格式变化后旧断言会假通过/假失败。正确：`reasons.some(r => r.includes("PERMANENT_TOMBSTONES_DROPPED"))`。
**出处**：`docs/20261019-0910-…-deepseek-v4.1-flash-1017.md`「修正误导性测试」「复审后修正」、`docs/20261013-0935-…-Step-5-Preview.md` §10

## 8. 死锁回归测试要模拟「永不返回」

**做法**：mock `chrome.runtime.sendMessage` 返回永不 resolve 的 promise，断言 `broadcastWebBridgeData` 在 10ms 内 settle。只测正常返回测不出死锁。
**教训**：事件循环单线程不等于无死锁；跨上下文消息通道 + Promise 互等同样会锁死。引入「等待某条件」的闸门时，必须排查所有进入该等待路径的调用方是否本身就在被等待链上。
**出处**：`docs/20261013-1315-…-Hy3.md`「回归测试」「教训」

## 9. Safari 实测的边界

- 用 Safari「开发者 → 添加临时扩展」加载独立目录，可在真实 IndexedDB/消息/回环 HTTP 上跑 10 项同步回归；逐字节比对测试后台与 `apps/extension_shared/dist/background.js`，证明跑的是当前产物。
- 结果只证明共享后台在临时扩展中通过，**不等于**原团队签名安装、自动填充、通行密钥 UI 全部验收。
- 结束要卸载测试扩展、关测试标签页、恢复「允许未签名的扩展」为关闭、关闭回环端口，不动用户原有会话。
- 测试服务不能把 `undefined` 写进幂等头；通过条件要求场景名称、顺序、成功状态全部匹配，不能把既有失败项跳过。
**出处**：`docs/20261008-1926-Safari扩展实测与发布收尾-GPT-6.md`
