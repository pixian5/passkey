# 前端表现层解耦与无构建单测

> 适用范围：Tauri 桌面 / Docker Web / Chrome 扩展 Web 管理界面。
> 阅读前提：`docs/` 是过程记录，可能过时；**冲突时以代码与最新实测为准**。
> 本文只保留「下次动手会用到」的结论。

---

## 1. 原生 ESM 同构分发：零打包器构建与跨端同步

**现象**：若为前端页面引入 Webpack、Vite 或 Rollup 打包链，会导致依赖锁定文件膨胀、离线/低带宽环境下无法拉取工具链，且 Chrome 扩展与 Docker Web 镜像的打包输出路径复杂易脱节。
**根因**：当前所有现代浏览器（Chrome、Edge、Safari、Firefox）及 Node.js 22+ 均对标准 ES Modules（`import` / `export`）提供开箱即用支持，非框架前端本质无需中间编译。
**正确做法**：
1. **源码单一事实**：所有前端代码以原生 ESM 规范维护在 `apps/codex-tauri/src/` 中。
2. **轻量静态同步**：利用 `prepare-dist.mjs` 与 `sync-web-ui.mjs`，在发布或构建时将源文件同构复制到 `apps/codex-tauri/dist/` 以及 `apps/extension_chrome_web/`。
3. **零构建运行**：Tauri 桌面、Web 容器和 Chrome 扩展管理页直接加载同一份静态 ESM 文件，极大提升可维护性与冷启动速度。
**出处**：`docs/20261108-0240-当前开发进度-antigravity.md`、`apps/codex-tauri/scripts/sync-web-ui.mjs`

## 2. 72 命令契约矩阵静态门禁防破坏

**现象**：在重构 Web 界面 RPC 调用或抽离通信切面时，若将调用语法改为 `adapter.invoke("command")` 或 `rpc("command")`，会导致门禁脚本 `scripts/check_command_matrix.mjs` 报 `MISSING_COMMAND` 失败。
**根因**：质量门禁通过静态正则（匹配 `invoke("command_name")`）扫描 `apps/codex-tauri/src/main.js`，确保三端 UI 发起的全部 72 个 RPC 契约均在 Tauri、Pass Web 与扩展后台得到完整实现。
**正确做法**：
1. 通信适配器抽离为 `PassClientAdapter`，但顶层必须保留原语绑定：
   ```javascript
   const defaultAdapter = new PassClientAdapter();
   const invoke = async (command, args = {}) => defaultAdapter.invoke(command, args);
   ```
2. 页面中各业务函数的调用点继续保持 `invoke("account_list", ...)` 写法，既实现了运行时的多端动态适配（Tauri `window.__TAURI__.core.invoke` vs 扩展桥接 `window.postMessage` vs Pass Web HTTP JSON-RPC），又 100% 契合静态门禁扫描。
**出处**：`apps/codex-tauri/src/adapter.js`、`scripts/check_command_matrix.mjs`

## 3. 核心算法与 DOM 彻底解耦，接入 Node 原生无构建单测

**现象**：以往 TOTP 生成、Google Authenticator Protobuf 迁移码解析、多字段模糊搜索、排序比较等前端逻辑内嵌在 DOM 事件监听中，只能人工在 UI 上点按验证，测试回归脆弱。
**根因**：纯计算逻辑与 DOM 渲染耦合，缺少纯函数边界，导致 Node.js 无法直接脱离浏览器环境执行单测。
**正确做法**：
1. **抽离纯函数模块**：
   - `totp.js`：RFC 4648 Base32、RFC 4226 HOTP、RFC 6238 TOTP、OTPAuth URI 解析、Protobuf Varint 解码；
   - `ui_utils.js`：`inferToastLevel`、`escapeHtml`、`isApplePlatform`、`isMultiSelectModifier`、`compareOptionalOrder`；
   - `vault_filters.js`：`accountRecordId`、`accountKey`、`isPinnedAccount`、`hasTotp`、`hasPasskey`、`folderIdsOf`、`matchesSearchQuery`。
2. **利用 Node 原生 WebCrypto**：模块内直接使用全局 `crypto.subtle`，在现代 Node.js 和浏览器中无缝同构。
3. **原生测试框架闭环**：在 `apps/extension_shared/tests/` 编写 `.test.mjs`，直接通过 `node --test` 运行，无需 Jest/Mocha 等额外依赖，数十毫秒内完成数百项用例校验。
**出处**：`apps/codex-tauri/src/totp.js`、`apps/extension_shared/tests/totp.test.mjs`、`apps/extension_shared/tests/ui_utils.test.mjs`

## 4. CSS 语义变量与原生多端深色模式

**现象**：深色模式下部分弹窗或背景出现局部发白、输入框占位符看不清、或依赖外部扩展强制注入滤镜反相。
**根因**：样式采用硬编码的十六进制颜色（如 `#ffffff`、`#333333`），且未声明标准 `color-scheme`，浏览器内置控件（如滚动条、系统表单元素）仍按浅色模式渲染。
**正确做法**：
1. 在 `:root` 中声明 `color-scheme: light dark;`，使浏览器原生滚动条和表单控件跟随系统配色自动反色。
2. 建立语义化设计变量：
   ```css
   :root {
     --bg-primary: #f6f8fa;
     --text-primary: #1f2328;
     --border-color: #d0d7de;
   }
   @media (prefers-color-scheme: dark) {
     :root {
       --bg-primary: #0d1117;
       --text-primary: #e6edf3;
       --border-color: #30363d;
     }
   }
   [data-theme="dark"] { /* 兼容用户手动切换主题 */ }
   ```
3. 业务组件样式严禁使用硬编码颜色，统一引用 `var(--xxx)`。
**出处**：`apps/codex-tauri/src/styles.css`

## 5. 前端内存擦除与选择模型解耦（SelectionModel / VaultStore）

**现象**：用户手动点击锁定或空闲超时锁定后，若仅在界面上遮罩弹层，前端内存的 `state` 变量仍旧持有全部账号明文与密码散列；且多选/范围跨选（Shift+Click）逻辑与 DOM 事件高度耦合，多端容易出现锚点错位。
**根因**：锁定状态未与数据存储生命周期深度绑定，状态重置逻辑散落在各处；列表多选采用松散全局变量，在过滤或删除后未对失效 ID 剪枝。
**正确做法**：
1. **面向对象封装 `SelectionModel`**：将单选（`selectOnly`）、反选（`toggle`）、连续范围跨选（`selectRange`）、全选（`selectAll`）、剪枝（`prune`）与清理（`clear`）收敛到类内部，用纯单测验证多选边界。
2. **锁定即擦除**：通过 `createEmptyState()` 与 `selection.clear()` 彻底清空内存中的账号、文件夹与选区数据，确保锁定状态下即使通过 DevTools 审查也无法从全局变量提取数据。
3. **数据变更安全剪枝**：每次刷新保密库时，自动对选区执行 `selection.prune(validIds)`，确保已被外部并发删除或移入回收站的账号不会留在多选操作集合中。
**出处**：`apps/codex-tauri/src/store.js`、`apps/extension_shared/tests/store.test.mjs`
