# 同步结果说明具体化：区分「真上传」与「内容一致跳过」，并点明覆盖方向

- 日期：2026-10-13 13:47
- 版本：1.9.3 → 1.9.4
- 触发：用户追问「远端已推送是什么意思」「我明明是从云端下载，怎么还要再推回去」

## 问题

同步成功后一律显示「本地已写入 · 远端已推送」，这个说法**不准确**：

- 报告里的 `pushed` 判定是 `confirmedTargets === targets.length`（background.js 703 行），
  而 `confirmedTargets` 在**真实上传成功**（659 行）和**内容一致跳过上传**（642 行，
  `push-skipped-remote-already-matches`）两种情况下都会 +1。
- 云端覆盖本地模式下，最终载荷就是云端原文（571 行
  `finalPayload = normalizeSyncPayloadShape(primaryRemotePayload || {})`），
  因此**经常压根没上传任何字节**，却仍显示「已推送」。
- 说明里也没说清是按哪种模式落地，「本地已写入」在覆盖本地/覆盖云端/合并三种
  模式下含义完全不同。

## 改动

### 1. 报告新增上传明细（可选字段，向后兼容）

- `apps/extension_shared/sync_report.js`：`uploadedTargets`（真上传成功的目标数）、
  `identicalTargets`（远端内容已一致、跳过上传但仍确认的目标数）。
  仅在传入时写入，`reportVersion` 保持 1，老报告不受影响。
- `docs/schemas/sync-operation-report-v1.schema.json`：补两个 integer 属性
  （该 schema `additionalProperties: false`，不补会导致校验失败）。
- `apps/extension_shared/background.js`：新增两个计数器，跳过分支计
  `identicalTargets`，`push-success` 分支计 `uploadedTargets`，随报告返回。

### 2. 结果文案按实际情况分情况说明

`apps/codex-tauri/src/main.js`（真源）与 `apps/extension_shared/options.js`
（扩展选项页）的 `formatSyncPushState` 同步重写：

| 情况 | 文案 |
| --- | --- |
| 覆盖本地 + 真上传 | 已用云端内容覆盖本地 · 已上传 1 个目标 |
| 覆盖本地 + 内容一致 | 已用云端内容覆盖本地 · 1 个目标内容已一致，未重复上传 |
| 混合 | 已上传 1 个目标，另 1 个内容一致未重复上传 |
| 合并 | 已合并写入本地 · … |
| 未推送待补偿 | 已用… · 远端未推送（待补偿重试） |
| 无需写入 | 两端内容已一致，无需写入 |
| 老报告无明细 | … · 远端已确认一致（兜底） |

### 3. 覆盖确认弹窗说明具体化

`main.js` 新增 `overwriteWarningText(mode)`，替换原先含糊的「会丢弃一侧的独有修改」：

- 云端覆盖本地 → 明确「以云端为准，本地被整份替换；**本地独有、云端没有**的
  新增与修改将被丢弃，无法通过合并找回」。
- 本地覆盖云端 → 明确「以本地为准，云端被整份替换；**云端独有、本地没有**的
  新增与修改将被丢弃（含云端已保留的永久删除墓碑）」。

仍是单次程序原生弹窗（`requestActionConfirmation`），未新增浏览器原生弹窗。
