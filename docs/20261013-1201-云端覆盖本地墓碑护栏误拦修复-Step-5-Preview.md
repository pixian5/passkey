# 云端覆盖本地被永久墓碑护栏误拦的修复（1.8.7）

> 关联文档：`docs/20261013-1124-合并永久墓碑163报错诊断增强-Step-5-Preview.md`（1.8.6 判决性诊断）
> 涉及版本：pass 1.8.6（缺陷暴露）→ 修复随 1.8.7 发布
> 状态：**已修复、已发版、测试全绿**

## 1. 现象（来自 1.8.6 诊断版的真实报错）

用户在扩展里点「云端覆盖本地」，报：

```
同步失败: Error:自建服务器 [SAFETY_BLOCKED]: 同步安全检查未通过:
PERMANENT_TOMBSTONES_DROPPED[accounts:dropped=163(req=195,merged=32,unflagged=0,absent=163) sample=(…); mode=remoteOverwriteLocal]
```

判决性诊断一击定位：
- `mode=remoteOverwriteLocal`：用户点的确是「云端覆盖本地」（不是合并）；
- `req=195, merged=32, dropped=163, absent=163`（本地独有墓碑 163 条、云端 32 条、无重叠）；
- `absent=163` 而非 `unflagged=163`：这 163 条记录在合并结果里**整体消失**（覆盖模式本就丢弃本地），并非标记被清。

## 2. 根因

`evaluateSyncSafety` 的永久墓碑护栏**不分同步模式**，对三种模式都用同一个 `required = 本地 ∪ 远端墓碑`：
- `merge`：两端都被合并保留，要求全保留合理；
- `remoteOverwriteLocal`（云端覆盖本地）：merged == 远端，本地独有墓碑按用户显式选择**本就该被弃用**，护栏却仍要求保留 → **覆盖按钮被永久拦死**；
- `localOverwriteRemote`（本地覆盖云端）：也是 WebDAV **镜像上传**所用模式，镜像须忠实反映删除、不能丢远端墓碑（防复活）——这一条必须保留「两端全保留」。

结论：缺陷只在 `remoteOverwriteLocal` 这一支；`localOverwriteRemote` 与 `merge` 保持不变。

## 3. 修复

**仅放松 `remoteOverwriteLocal`**：`required` 墓碑只取「被保留那一侧」——即远端墓碑；
本地独有墓碑被弃用不再拦截。仅当**远端墓碑本身**在合并结果里丢失时才拦截（防误删远端墓碑）。

`merge` / `localOverwriteRemote` 维持 `required = 本地 ∪ 远端`（后者保护镜像与防复活）。

- `core/pass_core/js/sync_merge_core.js` `evaluateSyncSafety`：`tombstoneSourcePayloads` 按 mode 取值；
- `core/pass_core/crates/merge/src/v2/safety.rs` `evaluate_sync_safety`：Rust 合并权威同步同样逻辑；
- JS↔Rust 对拍（48 例，仅验 `empty-remote-safety`）不受影响。

## 4. 测试

- `apps/extension_shared/tests/sync_merge.test.mjs`：新增/更新模式感知用例
  （云端覆盖本地本地独有墓碑→放行；远端墓碑被丢→拦截；本地覆盖云端/镜像仍须保留远端墓碑→拦截）；
- `apps/pass-web/src/sync_regression_tests.rs`、`apps/codex-tauri/src-tauri/src/sync/pipeline.rs`：
  原「冲突重试/回滚后保留墓碑」回归测试把 `RemoteOverwriteLocal` 分支断言为 `SAFETY_BLOCKED`（旧行为），
  已收敛为仅 `Merge`（覆盖模式按设计以服务端为准，其语义由单测单独覆盖）；
- 全量：`extension_shared 192/192`、`pass-merge 31/31`、`pass-web 23/23`、`codex-tauri 47/47`、
  JS↔Rust 对拍 48/48、`test_all.sh` 全绿（含 Rust fmt 与两应用 Rust 测试）。

## 5. 用户侧动作

1. 从 `apps/extension_chrome_web` **重载扩展** + 对目标页**硬刷新**（Chrome 不更新已开标签页的 content script）。
2. 点**「云端覆盖本地」**（蓝色按钮）——现在应能正常采用云端、弃用本地已删记录，不再被墓碑拦死。
3. ⚠️ **不要点「合并」**：合并是「删除赢」语义，会把本地这 163 个永久删除回灌到云端、把云端对应账号也删掉，
   是灾难性数据丢失。只有当本意就是「把本地删除同步到云端」时才考虑合并。
4. 同步编号若再出现新的 `SAFETY_BLOCKED`，把中括号整段贴回即可。

## 6. 遗留 / 安全提醒

- Bearer Token 仍是单字符 `9`（公网暴破风险），客户端侧建议换成 32 字节以上随机串，或重跑
  `rotate_token.sh` 后客户端同步更新。已多次提醒，待用户处理。
- CI 缺口：`version.mjs` 的 65 项校验不覆盖 Chrome `dist/*.js` 里的 `PASS_EXTENSION_VERSION`
  （需 bump 后先 build 共享层再 build-extension-chrome-web.sh 才能刷准），建议后续纳入校验。
