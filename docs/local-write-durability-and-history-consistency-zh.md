# 本地写入耐久性与历史一致性

## 背景

代码审查发现多集合顺序写入、保存失败后内存脏状态、撤销历史残留，以及同步服务器版本重复写入等问题。开发测试版允许直接修正，不兼容旧坏历史。

## 规则

1. 涉及账号、文件夹、全局排序、Passkey 的本地变更，必须同一事务写入。
2. 命令失败时，内存状态必须回到最近一次成功落盘状态。
3. 撤销栈忽略与当前状态相同的 no-op 条目，避免失败操作留下可撤销假记录。
4. 加密文件原子替换必须 `fsync` 临时文件和父目录。
5. 同步服务器每次成功写入只保存 1 个新版本；审计按 scope 保留上限；限流窗口清理过期 IP。
6. 主密码比较不 `trim`，首尾空格是有效密码字符。
