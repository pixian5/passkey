# 2026-07-26 代码复核与修复记录

本轮以代码实际行为为准，覆盖 Tauri、Docker Web、Chrome Web 扩展、旧 Swift 客户端和 Ubuntu 同步服务器。

## 已修复

- Chrome 扩展后台镜像现在双向同步：管理页写入后台，填充/WebAuthn/后台同步写入后广播回管理页。
- Chrome 扩展后台 IndexedDB 增加独立布局集合，保存 `allRegularAccountIds`、`folderOrderIds` 及其时间戳/设备名；账号、文件夹、通行密钥和布局使用同一个 IndexedDB 写事务。
- Chrome 自动填充候选按全局手工顺序排序；扩展命令会校验账号/文件夹 ID、归一化拖拽排序，并保持旧 `folderId` 与 `folderIds` 一致。
- Chrome 文件夹网站规则改为精确域名/子域名/已声明别名组匹配，避免 `notgithub.com` 误匹配 `github.com`。
- Chrome 管理页持久化失败时回滚内存缓存、撤销栈和快照栈；应用锁定时不再由管理页加载数据密钥。
- Web/Tauri 的 `localOverwriteRemote` 使用正确安全模式，远端为空时允许首次把本地数据推送到空服务器；同步冲突重试不再重复创建本地快照。
- Web 导出同步包/CSV 的路径限制在应用数据目录内，拒绝 `..` 和目录外路径。
- Tauri 服务器版本列表兼容数字型 `versionId`。
- Swift 同步包补齐顶层顺序字段，创建账号允许空用户名/空密码，恢复合并后按同步包顺序恢复数组；本地安全快照文件名保留备份原因。
- Rust 安全检查补齐远端实体丢失检查，与 JS 合并安全检查一致。
- Ubuntu systemd 模板不再强制 TLS 证书路径；同步成功后审计写入失败不再把已提交的数据伪装成客户端 500。

## 仍需单独处理的差异

- Chrome 管理页和后台仍保留两套运行时锁状态；当前通过消息镜像保持数据一致，但需要进一步统一锁定/解锁事件和失效时机。
- Swift 的文件夹内部顺序仍依赖账号字段/数组，尚未拥有与 Web/Tauri 相同的每文件夹顺序数组。
- Web/Tauri 文件存储仍没有跨进程 revision/CAS；部署环境必须保持单实例运行，直到补上版本比较和文件锁。
- 同步服务器限流目前按 TCP 对端地址；若放在反向代理后，应在部署配置中明确只信任受控代理来源，不能直接信任任意 `X-Forwarded-For`。
