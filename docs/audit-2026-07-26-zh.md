# 2026-07-26 当前程序与文档一致性审计

> 审计目标：以项目版本 `1.1.7` 的程序代码和自动化结果为事实来源，区分“已实现”“部分实现”“平台不支持”“历史方案”和“未来目标”。当前长期基准见 [`current-app-extension-implementation-reference-zh.md`](./current-app-extension-implementation-reference-zh.md)。

## 1. 审计范围和判断方法

本轮逐项检查：

- Tauri UI 调用的 68 个命令及 Rust handler；
- Docker Web `/api/invoke/:command`、vault 保存、锁和同步流程；
- Chrome Web bridge、加密管理工作区、后台 IndexedDB 镜像、填充和 WebAuthn；
- Rust/JS V2 类型、合并、安全评估和排序规范化；
- Ubuntu 同步服务器认证、ETag、幂等、版本、审计、TLS 和限流；
- 旧 SwiftUI、Firefox/Safari 壳、Android Provider 的实际定位；
- `docs/*.md`、两份 JSON Schema、Docker/systemd/README 和版本门禁。

判断约定：

- **已实现**：代码存在实际副作用，并有测试或门禁覆盖；
- **部分实现**：命令存在，但能力受平台限制、只保存草稿或返回形状未统一；
- **未实现**：只有路线图/设计描述，运行代码没有对应能力；
- **历史**：曾经的技术路线或旧客户端事实，不代表当前主端；
- **已知风险**：当前可运行，但没有满足多进程、生产部署或统一状态机要求。

## 2. 文档与代码差异及处理结论

| 原文/常见理解 | 代码事实 | 本轮文档处理 |
|---|---|---|
| Chrome Web 是“完整管理页”，可理解为所有桌面能力都支持 | 只共享管理 UI 和命令入口；WebDAV、SSH 执行、生物识别、原生选择器不支持 | 改成逐能力矩阵，不再用“完整”概括 |
| 三端命令 68/68 等于三端完全一致 | 矩阵只检查分支存在和少量返回契约；部分命令返回字符串/数字/布尔/`null` | 明确“覆盖不等于等价”，保留返回对象化待办 |
| Chrome 数据只在 `chrome.storage.local` | 加密管理工作区在 `chrome.storage.local`；业务集合还镜像到后台 IndexedDB | 写明两层存储、双向广播和双锁状态风险 |
| 所有多集合存储都天然具备跨进程事务 | Tauri/Chrome 有各自事务边界，Web 只有进程内 Mutex；Web/Tauri 无跨进程 revision/CAS | 明确单实例部署要求和最后写入者覆盖风险 |
| 设置页需要点“保存同步设置” | 同步、自动同步、WebDAV、设备名、UI 偏好和创建服务草稿均自动保存 | 写明 450 ms 防抖、`change` 保存及失败确认方法 |
| SSL 证书没有保存 | 证书/私钥路径属于创建服务草稿，会保存；只有 Tauri 会实际 SSH 部署 | 区分“保存草稿”和“执行创建服务” |
| 空 Bearer Token 是配置错误 | 当前服务器把空 Token 配置视为显式开放模式，并使用 `default` scope | 写明 401/403/open mode；禁止自动生成 Token |
| 空同步密钥仍会加密 | 空密钥传明文 V2 包，且服务器需允许明文 | 增加可信链路警告 |
| 同步是先推远端再写本地 | 当前合并模式先保存本地合并结果，再 PUT 远端 | 写明远端失败时本地已变化、需再次同步 |
| 服务器版本恢复只替换本机 | 客户端先 CAS 恢复远端为新当前版本，再刷新本地 | 写明恢复新增 revision，不删除之后的历史 |
| WebDAV 也有服务器版本列表 | WebDAV 只有单 JSON 资源和 ETag；版本接口属于自建服务器 | 从能力说明中拆开 |
| 同步包导入可能直接覆盖 | 导入固定为预览后字段级合并；覆盖仅属于远程同步模式 | 写明 `apply=false/true` 两阶段 |
| CSV 可作为完整备份 | CSV 不携带墓碑、关系时钟、Passkey 和完整排序 | 明确不能代替同步包 |
| 永久删除会物理移除记录 | 当前保留墓碑和稳定 ID，并清除敏感字段 | 写明可见数量和预览必须排除墓碑 |
| `regularSortOrder=-1/-2` 是现行顺序 | 当前以 `allRegularAccountIds`、文件夹 `regularAccountIds` 和 `folderOrderIds` 数组位置为权威 | 写明作用域数组、顶部插入和规范化规则 |
| 删除文件夹会同时删除账号 | 账号保留在全部账号，只移除文件夹归属并写关系墓碑 | 写入文件夹归属语义 |
| 撤销、快照、历史、服务器版本是同一套历史 | 四者保存位置、用途、保留数量和同步范围不同 | 新增独立对照表 |
| 旧 Swift 是“功能最完整”的当前主端 | 当前主端是 Tauri/Web/Chrome；Swift 只保留系统集成和迁移参考 | 修正路线图中的历史措辞并加状态警告 |
| Swift 与三端排序完全一致 | Swift 文件夹内顺序仍未采用每文件夹独立 `regularAccountIds` 权威模型 | 列为明确剩余差异 |
| Docker Web 三阶段已经全部完成 | 单用户核心已完成；Cookie 会话、多用户、WebAuthn 登录、授权审计和并发 CAS 未完成 | 给设计文档加“现状/目标”边界 |
| 同步服务器反向代理后会按真实用户 IP 限流 | 当前按 TCP 对端 IP；不会直接信任 X-Forwarded-For | 写入部署风险，不虚构代理信任 |
| `pass.data.v2` Schema 已覆盖全部当前排序字段 | Schema 有 `folderOrderIds`，但漏了顶层 `allRegularAccountIds` 三字段 | 本轮补齐机器 Schema |
| systemd 模板始终硬编码 `/etc/pass-sync/tls/*` | 通用模板从可选环境文件读取 TLS；只有 HTTPS SSH 创建流程生成的单元才写复制后的固定路径 | 修正过期脚本测试并记录两种部署入口 |
| `sqlite-schema.sql` 是当前主端数据库 DDL | 它与 `pass-storage` 候选迁移相同，但当前 Tauri/Swift 只建 KV 表，Web 使用加密 JSON vault | 标为历史/候选 DDL，禁止直接应用到现有数据库 |
| 本地同步服务器只会保存密文 | 同步密钥空且允许明文时，服务器保存可读 V2 包 | 修正本地服务器 README，写明空密钥与 `PASS_SYNC_ALLOW_PLAINTEXT` |
| 本地和 Ubuntu 启动脚本打印的 `/v1/sync/payload` 是当前推荐地址 | V1 只是兼容入口，主接口是 `/v2/sync/state` | 更新前台、launchd、Ubuntu 启动脚本输出并增加回归测试 |
| launchd 安装后会保留明文策略 | 原脚本只保存 Token，没有把 `PASS_SYNC_ALLOW_PLAINTEXT` 写入 plist | 安装时持久化明文策略并增加测试 |
| launchd 可以原样保存任意明文策略文本 | 服务只把 `1/true/yes` 解释为允许，其它值都拒绝，原样保存会造成显示与行为不一致 | 安装时只接受服务支持的布尔值并规范化为 `1` 或 `0` |
| 本地脚本打印的局域网 HTTP 地址可直接填入当前客户端 | Tauri/Chrome 只允许回环 HTTP，非回环地址必须 HTTPS | 文档和脚本区分监听地址、本机配置地址与跨设备 HTTPS 地址 |
| 本地脚本可把 Token 打印给用户复制 | 原脚本会把完整 Token 输出到终端，可能进入日志或截图 | 改为只显示是否配置，并增加不泄漏断言 |
| 项目不会生成 Token，但 `rotate_token.sh` 可以例外 | 轮换脚本仍调用 `openssl rand` 并回显新 Token | 改为只写入用户提供的 Token，不生成、不回显，并纳入全局脚本测试 |
| Token 轮换脚本写入任意文本后都算成功 | 服务以逗号分隔多个 Token，空白也不属于 Bearer Token；原脚本还存在新文件在 `chmod` 前短暂沿用默认权限的窗口 | 写入前拒绝逗号/空白和非法 scope，并以 `umask 077` 从创建时保护文件 |

## 3. 当前已经落实并应保持的行为

### 3.1 数据和排序

- 账号、文件夹、Passkey 使用稳定 ID；永久删除记录是墓碑。
- 用户名和密码不是必填；站点仍是账号识别入口。
- 文件夹归属、站点别名、Passkey 关联都有关系墓碑。
- 全部账号、每个文件夹和文件夹侧栏分别拥有独立顺序数组和时钟。
- 新建、新加入和恢复账号进入相应普通区顶部；批量操作保持原相对顺序；已有成员不重排。
- 文件夹删除后账号仍在全部账号；恢复只回到仍存在的原文件夹。

### 3.2 本地写入和历史

- Tauri 关联集合通过 SQLite 事务写入；Chrome 后台业务集合通过同一 IndexedDB 事务写入。
- Web vault 和相关密钥采用临时文件、文件 `fsync`、rename、目录 `fsync`。
- 保存失败回滚内存；失败操作不提交有效撤销项。
- 撤销/重做历史最多 100 条；本地安全快照最多 20 个。
- 撤销、重做、同步、导入和恢复等高风险替换前会创建本地快照。
- 历史只展示动作摘要，不保存密码、TOTP、恢复码或备注正文。

### 3.3 同步和恢复

- 自建服务器三端可用；Tauri/Web 支持 WebDAV，Chrome 明确报不支持。
- 预览不写本地、不推远端；同步包导入必须预览并确认。
- 空 Token 和空同步密钥均允许；项目不会自动生成 Bearer Token。
- 自建服务器用 ETag/If-Match、412/428 和幂等键保护并发写。
- 合并同步先写本地再推远端；远端失败不能回报为全部完成。
- 每次成功 PUT 或恢复只新增一个服务器版本；每 scope 保留 50 个版本、5000 条审计。
- 审计保存失败不再把已经成功的业务提交伪装成 HTTP 500。

### 3.4 UI 与扩展

- Tauri UI 是三端管理页唯一源码；扩展生成文件不可手工维护。
- 预览、同步、导入、创建服务等耗时按钮使用忙碌状态，不应长期阻塞 UI 线程。
- 编辑账号底部操作栏固定，滚动内容必须预留空间；扩展填充列表使用独立滚动容器。
- Chrome 管理页写入后台，后台填充/WebAuthn/同步变更会广播回管理页。
- Chrome 自动填充按全局手工顺序；站点匹配使用精确域名、子域和显式别名组，不能用任意字符串包含。

## 4. 尚未解决、不能写成已完成的事项

### P1：运行一致性风险

1. **Chrome 双锁状态**：管理页与 service worker 各自保存锁运行时，消息镜像不能保证所有失效边界一致。
2. **跨进程写冲突**：Web/Tauri 数据目录没有文件级 revision/CAS；只允许单实例写。
3. **Schema/实现漂移门禁不足**：命令矩阵不校验全部返回 Schema；JSON Schema 也没有自动覆盖 Rust 所有字段。

### P2：架构尚未统一

1. Chrome 使用 JS merge 而不是 Rust/WASM；必须继续靠黄金向量守住语义。
2. 排序数组、撤销栈、快照和部分 mutation 仍由各端适配层实现，不是全部进入共享 Core。
3. 旧 Swift 文件夹内顺序、锁和本地历史模型不等同于三端主实现。
4. Firefox/Safari/Android 尚未接入三端命令矩阵，不能宣称管理能力一致。

### P3：产品和部署缺口

1. Docker Web 只有单用户 vault，没有 Cookie 会话、多租户授权、WebAuthn 登录、管理员审计和跨进程 CAS。
2. 同步服务器限流按 TCP 对端 IP；反向代理可信头策略尚未实现。
3. 远程 Ubuntu 实机部署、多架构镜像发布、生产自动回滚仍需在对应环境验证。
4. 软件 Passkey 私钥可同步，不等同硬件认证器的不可导出保护。
5. Rust 全仓格式检查仍有既有差异，当前 CI 只把它作为 informational。

## 7. 验证要求

文档修改不能只检查 Markdown 是否能打开，还必须验证其引用的数字和契约：

```bash
node scripts/version.mjs check
node scripts/check_command_matrix.mjs
node core/pass_core/js/check_merge_parity.mjs
bash scripts/core_gate.sh
```

还应执行 Markdown 相对链接检查、JSON Schema 解析、旧版本号搜索和 `git diff --check`。版本/测试数量变化后，必须更新当前实现基准，历史章节中的旧数字则保留并明确标注历史版本。
