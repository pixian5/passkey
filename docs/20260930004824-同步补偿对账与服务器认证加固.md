# 同步补偿对账与服务器认证加固（2026-09-30 00:48）

版本 `1.7.9`。本轮是只读评审之后的修复轮，只改同步相关代码、部署脚本与文档，不动其它模块逻辑。

## 1. 问题根因

### 1.1 明文同步确认门槛（按用户要求保持原状）

同步加密密钥留空时 `confirmPlaintextSync` 直接返回 `true`，且服务端默认 `PASS_SYNC_ALLOW_PLAINTEXT=1`。用户明确决定：**不增加额外确认开关**，配了同步密钥就加密，没配就直接按协议明文同步，不额外弹窗。本轮保留该行为，并把它写进契约文档，避免后续再被当成缺陷反复改动。

### 1.2 无 Token 启动即开放访问（已修复）

令牌文件缺失且没有环境令牌时，服务只写一条 warning 就以开放模式启动；`start.sh` 还默认监听 `0.0.0.0`。对外反向代理场景下，令牌漏配等于把同步状态公开。

### 1.3 补偿重试撞上幂等键绑定（已修复）

outbox 只保存业务 payload 与幂等键，不保存已发送的 wire body。重试时 `exportedAtMs` 改变、AES-GCM nonce 重新随机，请求体摘要随之改变；服务端把 `Idempotency-Key` 与 payload 摘要绑定，旧键发新体会被判 `IDEMPOTENCY_KEY_REUSED`。若上一次 PUT 实际已提交、只是响应丢失，客户端会长期无法收敛。

### 1.4 `412` 后回读失败绕过补偿队列（已修复）

冲突重试期间的重新拉取错误直接向上返回，而主命令只在收到 `pending_retry` 报告时才写 outbox；本地可能已经写入合并结果，形成“本地已应用、远端未补偿、队列为空”。

## 2. 修复内容

### 2.1 服务器：开放模式必须显式

- `AppConfig` 增加 `allow_open`，`build_server` 与 `load_config` 双重校验；无 Token 且未显式开启时拒绝启动（`apps/sync_server_ubuntu/pass_sync_server.py`）。
- `start.sh`（Ubuntu 与 macOS 本地）默认监听 `127.0.0.1`，无 Token 时必须显式 `PASS_SYNC_ALLOW_OPEN=1`。
- `install-launchd.sh` 同样要求显式开放开关，并把 `PASS_SYNC_ALLOW_OPEN` 持久进 plist。
- systemd 模板注释改为“未配置令牌时服务拒绝启动”。
- Tauri provisioning：目标 URL 为 HTTPS 时必须提供 Bearer Token；生成的环境文件同时写入 `PASS_SYNC_ALLOW_PLAINTEXT` 与 `PASS_SYNC_ALLOW_OPEN`，两项语义独立。

### 2.2 补偿对账：先比对，再决定是否重写

- Tauri `run_sync_with_transport_context`：新增 `reconcile_remote`；冲突后回读失败时返回 `pullingRemote` 阶段的 `pendingRetry` 报告；PUT 结果不确定时先回读远端，业务载荷一致即按成功收敛。
- outbox 重试上下文改为新幂等键 + `reconcile_remote=true`，旧提交先通过拉取核对，避免旧键绑定新请求体。
- Docker Web（`apps/pass-web/src/main.rs`）：抽出 `parse_remote_sync_payload` 与 `pending_sync_failure`，自建服务器与 WebDAV 两条链路都具备“回读确认”和“冲突后回读失败入队”；确认远端已提交时补齐本地写入并清队列。
- 扩展（`apps/extension_shared/options.js`、`apps/extension_shared/background.js`）：推送前若远端已等于候选 payload 则跳过写入并清队列；outbox 项对应的重算写入一律使用新幂等键。
- 本地写入时机：仅在确认远端已提交且本地尚未应用时才补齐本地，避免把未确认结果写进本地 vault。

### 2.3 永久删除墓碑在覆盖模式下不可丢弃

- Rust `evaluate_sync_safety` 与 JS `evaluateSyncSafety` 新增 `PERMANENT_TOMBSTONES_DROPPED`：任一侧永久删除墓碑缺失即阻止写入，merge 与 remoteOverwriteLocal/localOverwriteRemote 都生效。
- JS/Rust 对拍与共享 Node 测试同步覆盖该规则。
- 扩展选项页安全检查改为按实际模式求值，不再硬编码 merge。

修复前的同步相关未提交改动已备份到 `/tmp/pass-sync-preexisting-20260929231504.patch`（含此前的 alias 固定时钟与明文确认改动）。本轮修改与其共存，未回滚任何既有内容。

## 4. 经验

- 幂等键必须和请求体绑定；只要 envelope 会随时间戳/nonce 变化，重试要么重放同一请求体，要么换新键。
- 冲突重试期间的回读失败必须结构化，否则“本地已写、远端未写”会从补偿队列里漏掉。
- “无认证开放”不应由配置缺失推导出来；显式开关加默认拒绝，才不会因漏配而暴露。
- `cp -R 新.app /Applications/同名.app` 会把新包嵌进旧包目录形成 `/Applications/X.app/X.app`，不会替换。正确做法：确认旧进程退出后先把旧 `.app` 移到备份路径，再复制新包，并校验 `Info.plist` 的 `CFBundleShortVersionString` 与二进制时间戳。
- 直接运行 GUI 二进制的 `--version` 会挂住（无参数即进入图形循环）；版本应读 `Info.plist`，或用 `open -a` 后查进程验证。
