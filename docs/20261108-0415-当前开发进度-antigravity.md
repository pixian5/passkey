## 本轮核心交付

### 1. 三端本地存储 CAS 契约对齐（Phase 5 落地）
- **Tauri SQLite 底层支持 `business_revision`**：
  - 在 SQLite KV 存储中引入 `KEY_BUSINESS_REVISION = "business_revision_v1"`，默认初始值为 `0`。
  - 实现 `read_business_revision` 与 `write_business_revision`。
  - 在 `save_collections_atomic_with_guard` 中对所有涉及账号、文件夹、顺序、通行密钥的业务写操作统一执行 `rev + 1` 递增。
  - 支持可选的 `expected_revision: Option<i64>` 乐观并发校验，如版本不匹配则原子回滚并拒绝写入，返回标准错误：`LOCAL_CHANGED: 本地业务版本已变化（期望 {expected}，实际 {current}），请重新同步`。
  - `AppState` 结构体新增 `business_revision: i64`，并在 `get_app_state` 中同步暴露给前端。
- **Pass Web 加密持久化底层支持 `business_revision`**：
  - `VaultData` 与 `AppStateOutput` 新增 `#[serde(default)] business_revision: i64`。
  - `Vault::save_with_guard` 实现版本递增与 `expected_revision` 一致性断言，冲突时返回 `LOCAL_CHANGED`。
  - `app_state(&VaultData)` 保证 `business_revision` 实时同步返回前端。
- **Web 响应式 Store 状态模型对齐**：
  - `apps/codex-tauri/src/store.js` 中的 `createEmptyState` 新增 `businessRevision: 0`。
  - `normalizeAppState` 统一兼容并归一化下划线 `business_revision` 与驼峰 `businessRevision`。

### 2. 自动化测试与质量闭环
- **Tauri Rust 单元测试**：新增 `local_business_revision_increments_and_guards_against_stale_expected_revision`，闭环初始版本读取、正确版本保存递增、过期版本写入阻断与 `LOCAL_CHANGED` 抛错。
- **Pass Web Rust 单元测试**：新增 `local_business_revision_increments_and_guards_against_stale_expected_revision`，覆盖多版本连续演进与状态读取。
- **前端 Node 单测**：更新 `apps/extension_shared/tests/store.test.mjs`，确保 `businessRevision` 结构与归一化正确，240 项前端单测全绿。

### 3. 经验沉淀
- 新增 [`经验/07-本地存储Revision乐观并发锁与多端一致性.md`](../经验/07-本地存储Revision乐观并发锁与多端一致性.md)，提炼三端本地并发写冲突根因、写操作原子递增规范及向后兼容规则。
